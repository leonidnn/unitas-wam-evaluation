# Проекция сохранённого прогноза SceneFlow

`project_prediction.py` сопоставляет начальное облако с исходными RGB-D и строит проекции траекторий сцены и захвата на изображения камер. Модель не запускается, CUDA и веса не нужны. Использованы соглашения авторской `src/unitas/scene_flow/io.py::backproject_queries`: внешняя матрица переводит координаты модели в камеру, глубина соответствует camera z, центры пикселей заданы как `(u+0.5,v+0.5)`.

Зависимости: NumPy и Matplotlib. Команда из корня проекта:

```bash
python src/stage2_transfer/project_prediction.py --input assets/scene_flow/observations/libero_3d040e000e_0077.npz --prediction outputs/stage2/libero_3d040e000e_0077/scene_flow.npz --output-dir outputs/stage2/libero_3d040e000e_0077/projections-repeat
```

Каталог вывода должен быть новым. Скрипт сохраняет:

- `cam*-alignment.png` — исходный RGB, проекцию начального облака и разность глубины;
- `cam*-trajectories.png` — начало, середину и конец прогнозируемых траекторий на исходном RGB;
- `initial-masks.npz` — начальные маски и индексы выбранных точек;
- `inspection.json` — матрицы, команду, версии, контрольные суммы, численные проверки и параметры выбора точек.

Проверяются совпадение начальных точек прогноза с входом, конечность координат и обратимость преобразования depth → 3D → pixel. Для начальной маски требуются положительная глубина, попадание в кадр и согласование с исходной depth-картой при допуске 1 см. Параметр `--depth-tolerance-m` задаёт допуск; отдельно записаны количества для 2/5/10/20 мм. Эти величины характеризуют исходное совмещение, а не ошибку будущего прогноза или точность физической калибровки.

Для рисунков выбираются 500 равномерно расположенных индексов среди начальных depth-совместимых точек каждой камеры, без отбора по движению; количество задаётся `--scene-trajectories`. Индексы фиксируются на всём горизонте. Все идентификаторы точек захвата проецируются отдельно, без depth-фильтра. Будущая окклюзия неизвестна, поэтому начальная карта глубины не применяется как маска будущей видимости.

Во всех панелях используются начальные RGB и начальные позы камер. Для камеры на запястье это виртуально неподвижный исходный ракурс; рисунок не воспроизводит движение реальной камеры. Выход за рамку кадра и большой перспективный сдвиг сами по себе не доказывают ошибку 3D-динамики. Скрипт не вычисляет ADE/FDE: для них нужны независимые эталонные будущие соответствия.
