# Формат оценок и механическая обработка

Все пути команд ниже считаются относительно папки skill. Python 3.10+; зависимости помощника — NumPy, Pillow и Matplotlib. FFmpeg используется только для декодирования/перекодирования и временных меток. Передай его через `--ffmpeg`; также поддерживаются PATH и уже установленный `imageio_ffmpeg`. Новые анализаторы или загрузка весов не нужны.

```bash
python scripts/media_io.py inspect --video ../videos/WIN_20261112_10_59_15_Pro.mp4
python scripts/media_io.py preview --video ../videos/WIN_20261112_10_59_15_Pro.mp4 --work-dir ../prepared/cup-001 --until 0
```

Последующие preview увеличивают `--until` на 0.5 с. `exposure.json` фиксирует наибольшую границу выгруженных кадров, а не обещает, что модель их не видела. Когда выбран момент T:

```bash
python scripts/media_io.py extract --video ../videos/WIN_20261112_10_59_15_Pro.mp4 --work-dir ../prepared/cup-001 --cutoff T
python scripts/media_io.py validate --work-dir ../prepared/cup-001
python scripts/media_io.py render --work-dir ../prepared/cup-001
python scripts/media_io.py pack --work-dir ../prepared/cup-001
python scripts/media_io.py render --work-dir ../prepared/cup-001
```

T здесь — выбранное числовое время, не буквальная строка. При прямом запуске из корня проекта передавай полные относительные пути к помощнику и файлам. Новое извлечение требует нового рабочего каталога; render можно повторять после исправления JSON. Pack не перезаписывает существующий NPZ.

## Файлы рабочего каталога

- `exposure.json` — источник и монотонно растущая граница preview.
- `manifest.json` — разрешённая история, SHA-256 кадров, исходный размер, целевые/реальные времена, повторные кадры, SHA-256 видео, граница и длительность отложенного интервала.
- `frames/` — исходные PNG разрешённой истории; `input.mp4` — только её просмотр без аудио и метаданных источника.
- `heldout/future.mp4` — следующая секунда, исключённая из подготовки. Не открывать разметчику.
- `annotations.json` — основной результат прямого анализа модели.
- `validation.json`, `figures/`, `report.md` — проверки и иллюстрированное представление оценок.
- `input.npz`, `input-provenance.json`, `estimate-masks.npz` — экспериментальный вход и происхождение. Не маскировать происхождение псевдоглубины.

## Координаты и значения

`uv` — нормированные координаты центров пикселей: `u=(x+0.5)/W`, `v=(y+0.5)/H`, начало сверху слева; диапазон [0,1]. K относится к исходному размеру кадра, в пикселях. Модель оценивает положительные fx/fy, cx/cy, нулевой skew и отсутствие дисторсии как явно записанное приближение; K имеет последний ряд [0,0,1].

Глубина `z_m` — координата вдоль оптической оси, не евклидово расстояние. `X_camera = z·K⁻¹·[uW,vH,1]`. Сетка глубины равномерно покрывает весь кадр; строка 0 сверху, столбец 0 слева. При упаковке она механически увеличивается nearest-neighbor до 224×224; новые детали при этом не восстанавливаются. RGB уменьшается до 224×224 bilinear, строки K масштабируются отдельно по ширине и высоте.

Начало системы модели — `table.origin_camera_m` под кружкой в текущем кадре. Ось +Z задаёт нормаль стола вверх. +X — проекция направления camera-right [1,0,0] на плоскость стола; +Y=+Z×+X. Матрица model→camera состоит из этих осей и начала. Это выбранная система собственной сцены, а не измеренная база Panda.

Для условной EEF-позы используй одну и ту же точку хвата и соглашение ориентации на всей истории. Положение и quaternion xyzw оцениваются в системе камеры; помощник переводит их в систему модели. `open_fraction` — условное раскрытие [0,1], где 1 — открыто. Оно не описывает пять независимых пальцев. Неопределённая поза — `null` со статусом unknown; нулевые заглушки в NPZ всегда сопровождаются false-маской.

## annotations.json, версия 1

Корневые ключи:

| Ключ | Тип и смысл |
|---|---|
| `version` | строка `llm-scene-v1` |
| `manifest_sha256` | SHA-256 точного manifest.json |
| `analysis_method` | строка `direct_visual_reasoning` |
| `external_vision_models` | пустой массив |
| `instruction` | непустая команда, зафиксированная без будущего |
| `scale` | `object_id`, `height_m: 0.11`, `source: user_measured`, `notes` |
| `camera` | `intrinsic` (3×3 либо null), `status: estimated/unknown`, `distortion_assumption: zero`, `notes` |
| `camera_stationary` | `yes/no/uncertain`, результат визуального суждения |
| `table` | `origin_camera_m` (3 числа либо null), `up_normal_camera` (3 числа либо null), `status: estimated/unknown`, `notes` |
| `depth` | `width:64`, `height:36`, `kind:camera_z`, `units:m`, `status:estimated`, `values_m`: 36 рядов по 64 положительных числа или null |
| `objects` | объекты текущего кадра, формат ниже |
| `history` | ровно 21 запись в порядке manifest.history |
| `assumptions` | массив непустых описаний предположений |
| `limitations` | массив описаний неизвестного/ограничений |

Объект: `id` (уникальная строка), `label`, `polygon_uv` (не менее трёх пар uv), `status` (`visible` или `inferred`), `occlusion_notes`. Обязателен объект кружки с id=`scale.object_id`. Полигон показывает оценённую границу, не точную сегментацию. Перекрытия описываются явно. Помощник растеризует заданные полигоны, не распознавая пиксели.

Запись истории: `sample` (0..20), `landmarks` (21 запись), `eef` и `notes`. Целевые времена, реальные времена и повторы берутся из manifest по sample и не переписываются моделью.

Landmark: `id` (0..20), `uv` (пара либо null), `z_m` (положительное число либо null), `status` (`visible`, `inferred`, `unknown`). Для unknown значения null. Для visible/inferred нужны uv и z_m. «Visible» относится к различимости точки на изображении; её глубина во всех случаях оценена.

Постоянный порядок: 0 — запястье; 1–4 — большой палец CMC/MCP/IP/кончик; 5–8 — указательный MCP/PIP/DIP/кончик; 9–12 — средний; 13–16 — безымянный; 17–20 — мизинец. Точки 1–20 входят в history_robot_flows, запястье остаётся в JSON и масках. Не меняй местами пальцы при перекрытии.

EEF: `status` (`estimated/unknown`), `position_camera_m` (3 числа либо null), `quaternion_camera_xyzw` (4 числа ненулевой нормы либо null), `open_fraction` ([0,1] либо null). Неизвестная EEF делает этот исторический шаг невалидным для NPZ; текущая EEF обязательна для готового входа. Положение/ориентацию нельзя выдавать за измеренную кинематику.

Нельзя заполнять `annotations.json` демонстрационными числами из тестов. Тестовые сцены не являются разметкой пользовательского видео.

## Экспорт UNITAS

Совместимость формата сверяется с src/unitas/scene_flow/io.py и inference/preprocessing.py проекта. Человеческая рука кодируется экспериментально через domain=libero, без изменения исходников модели и без штатного FK-адаптера Panda. Это совместимость контейнера, не семантики обучения.

- `history_robot_flows`: [1,21,20,3], координаты модели; `history_robot_exists`: [1,21,20].
- `history_eef_poses`: [1,21,2,7], xyz+xyzw; `history_eef_open`: [1,21,2,1]; `history_eef_exists`: [1,21,2]. Активен только слот 1; слот 0 не означает вторую руку.
- `history_valid_mask`: [1,21]; `history_frame_indices`: [1,21], от −20 до 0. Реальные времена сохраняются в provenance, повторные кадры отмечаются; данные не интерполируются.
- Все три flow_fps=20 и flow_horizon=20; соответствие должно быть сверено с выбранным checkpoint перед отдельным инференсом.
- cam0 существует; cam1/cam2 — нулевые placeholders с exists=false, не дополнительные наблюдения.
- `xyz0` — только пиксели с положительной оценённой глубиной; `colors` — цвета исходного текущего RGB после изменения размера. Неизвестная глубина равна 0 в depth-тензоре и исключена из query cloud.

Готовность требует корректной структуры, совпадения manifest и кадров, неподвижной камеры по оценке разметчика, K и стола, текущей EEF, хотя бы одной доступной точки пальцев в текущем кадре, положительной глубины и полигона кружки. Плохо обусловленная геометрия или неизвестное обязательное поле дают not_ready. Низкое покрытие, inferred-точки и условность EEF отражаются в отчёте даже при технической готовности. Никакая проверка здесь не разрешает называть оценки ground truth или считать метрические ADE/FDE.
